# 1-hour soak: hosted SPI + AFE FD HIGH + I2S link (final cp_s3 configuration)

English | [Tiếng Việt](vi/2026-11-23_phase5_soak_1h.md)

Started at 21:31 on 2026-11-23. TCP RX PC->P4 for 30 minutes, then TCP TX P4->PC for 30 minutes, at the same time as the I2S link (silent playback) and the AFE running.
SPI 26 MHz, esp_hosted 3.1.0, hosted task stack 6144, stream buffers in PSRAM.

| Metric | RX 30 min | TX 30 min |
| --- | --- | --- |
| Average TCP throughput (10 s intervals) | 10.2 Mbps | 9.3 Mbps |
| Lowest / highest | 0.55 / 13.5 | 3.2 / 15.9 |
| Intervals below 1 Mbps | 1 | 0 |
| I2S frames received (16 kHz) | 29,039,488 (1815 s) | 29,039,488 (1815 s) |
| Frame counter errors | 1 (at start) | 1 (at start) |
| Read timeouts | 0 | 0 |

Whole run:
- The S3 did not restart after the start. The S3 error lines are two familiar start-up errors (`gpio` isr service, `req_wifi_sta_get_ap_info` before the connection).
- P4: no TRANSPORT_FAILURE, checksum error, full queue or panic.
- tx_drop = 0, rx_overrun = 0: the two I2S clock domains (codec and link) did not drift apart in one hour.
- S3 minimum internal RAM: 39 to 40 KB, steady (not decreasing); 104 KB when idle. Threshold 40 KB: tight, almost met.
- S3 CPU: core 0 average 38% (max 58.6%), core 1 average 45.5% (max 60.2%, right at the 60% threshold). Both within the plan thresholds except that core 1's peak just touched the limit.
- AFE lag: average 13 ms, maximum 26 ms.

Not measured: 8-hour soak, BLE together with WiFi, decoding FPS on the P4, speech through the speaker during the soak (playback was silent).
